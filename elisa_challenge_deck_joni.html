Veikko · field engineerChanged the SFP on TRN-042. Link is up, alarms cleared, but no traffic. Seen this before?

VeikkoYes, around 2019.
ErkkiDon't trust the green link status on those. Are the counters increasing?

Veikko has replaced an SFP. Everything is green but there's no traffic. The natural conclusion is that the new SFP is bad: swap it again or reboot. He pings Erkki on Teams. "Older unit? How we model the network
Intent / design as-designed
Physical / passive as-built
Runtime / active as-running
Context as-experienced · missing
Event stream as-observed
Decades of data tell us WHAT Nothing captures WHY

Workarounds · site access · why a config is odd · what actually fixed it

We describe the network in layers: as-designed, as-built, as-running (topology and telemetry), and the as-observed event stream. They tell us WHAT. The context layer, as-experienced, is the WHY. It lives in heads, Teams chats, emails and calls, and it leaves when people do.
Reference architecture (in your material)
  • Time-aware layers
  • Each context assertion is bound to a graph entity
  • Has valid_from / valid_to
  • Cross-reference all layers at any point in time
This is the reference model from the brief. Every context assertion is bound to a graph entity and has a validity window. valid_to defaults to "still believed true".
For a human-run network, this was annoying.
For an autonomous one, it's a hard stop.

The challenge
Capture human-generated knowledge, bind it to the right network context, and make it available to AI agents, so that autonomous workflows can run end to end.
Read the statement. Then move to the guiding question, which is the one that matters most.
Guiding question
How could we collect silent metadata without creating additional work for our specialists?
Why is "no additional work" the core? Because the other way has been tried, by us and by every company: "Please document this in the wiki." "Please write a proper closure comment." Documentation is always the first thing to go.

What makes it hard

Harder than it looks

01

The real knowledge

Twelve messages of chat, about one sentence of actual rule.

02

Linking

"These older units": TRN-042 only? The model? Install year? A wrong link is worse than none.

03

Time

Firmware fixes the bug and the barrier gets a new lock. When does it stop being true?

04

Trust

Hunch or verified fix? Two experts disagree? Who said it, and where?

05

People

These are colleague conversations. How does it feel to be on the other side?

I won't tell you how to solve these, but think about them. The rule: on older units, after an SFP swap, UP plus normal optics plus zero counters means a forwarding-state issue, so bounce the interface first. Linking: an autonomous system will act on a wrong link confidently. Time: that's why valid_from and valid_to exist.
