# Team-chat clone (Microsoft Teams look) for the demo

Spec: `docs/TEAMS_CLONE_HANDOFF.md` and `docs/DEMO_CHAT.md`. Vite + React 18 + TypeScript, plain CSS, vitest.

## Run

```powershell
cd ui
npm install
npm run dev        # http://localhost:5173
npm test
npm run build
```

- **Replay** (what the video records): `http://localhost:5173/?beat=N`, N = 1..9 (as many as there are beat files). Shows the cumulative state after beat N.
  Optional `&channel=faults|experts|site-access|field-chat|general` opens that channel first.
- **Reveal** (recording like a live chat): add `&reveal=1`. The channel opens at the previous beat's state; Space or Right
  shows the beat's next item (with typing row and animation), Left hides the last, a click on the invisible 40 px strip at the
  right edge of the posts also advances. `&reveal=auto&every=1400` advances by itself, `every` ms after each item lands.
  Durations: `TIMING` in `src/reveal.ts`. Without `reveal` nothing changes.
- **Live**: no `?beat`. "Report fault" (channel header) and the question buttons call the API.

## Switch to the backend

```powershell
# repo root
$env:LLM_OFFLINE="1"; py -3.14 demo.py
uvicorn api.app:app
# ui/
$env:VITE_DATA_SOURCE="api"; $env:VITE_API_URL="http://localhost:8000"; npm run dev
```

`src/data/index.ts` is the only place that knows which source is active. Mock mode cannot run new incidents
(Report fault shows an error); answers in mock mode are kept in memory.

## Refresh the mock data

After `demo.py`, copy `out/*.json` into `src/data/mock/` byte for byte. Provenance of every file: `src/data/mock/README.md`
(Elisa's: thread-001, email-001; generated by `gemini-3.5-flash`: filler chats, barrier email and update; hand-written:
Sami's thread, the TRN-087 and TRN-101 reports).

## Where things are

- `src/data/`: the data layer (`types.ts`, `mockSource.ts`, `apiSource.ts`, `fixtures.ts` for the mock-only files, `vocabulary.ts`).
- `src/model.ts`: turns backend data + beat into channels and posts. Holds the replay filters (handoff section 4) and the
  STATUS template, the only frontend copy near the agent: `"<Name>'s tip does not apply: {reason}."`,
  `"<Name>'s tip may apply: {reason}. Question sent to {question.to}."`.
- `src/App.tsx`, `src/Thread.tsx`, `src/ReportFault.tsx`, `src/icons.tsx`: the Teams chrome and posts.

## Layout decisions

Team "Network Operations": **Faults** (one post per incident: TRN-087, TRN-101, TRN-105; STATUS and proposal as replies),
**Experts** (thread-001 and Erkki's email; question cards and notices land here), **Site access** (barrier email, key-update
thread, OULU-03 dispatch), **Field chat** (the seven filler chats), **General** (empty).

Beat 1 and beat 3 are the same TRN-087 incident against different stores; from beat 3 the beat-3 run replaces the beat-1 one.
Same for the OULU-03 dispatch in beats 5 and 6. A notification whose `at` maps to an earlier beat than its thread appears with
the thread (Veikko's OULU-03 notice: `at` says beat 5, thread-12b and CA-0003 exist from beat 6).

Beat 8 adds thread-14 (road closed) to Site access and two OULU-11 dispatch posts: 15 Nov from `results_before` (proposal)
and 21 Nov from `results_after` (declined, expired; the tip struck through with its `valid_to`). Those two posts show only the
beat's own assertion (`data.assertions`, CA-0004); the unrelated CA-0002/CA-0003 declines in the same lists are left out.
Beat 9 adds thread-15 (Erkki's retraction) to Experts as its own post, with the STATUS line of `beat_9.data.results` under
Erkki's message, and a TRN-087 post on 11 Nov with the declined ("under review") card. The beat range comes from the beat files.

## Asked of the backend

   `results[].assertion.action_text` verbatim (still a backend string), because no `agent_text` exists for those beats.

   The UI takes the time from the report message or the notification, and for beats 8 and 9 from a small table in
   `src/model.ts` copied from the printed `lines`.

4. The chosen `option_index` on answered questions in thread files (today only `answered: true`; the label comes from
   `beat_N.data.answer`, or from the click in live mode).
